# v1.0.0 四 AI 评审整改记录

评审来源：DeepSeek、Gemini、Grok、通义千问（各报告均基于项目说明，未核查原 HTML）。本轮以实际 v0.1.0 HTML 源码逐项对照。

## 采纳并实施

- 保留全部 38 个检查编号和六大模块，无新页面和外部依赖。
- 强化 WordPress 搜索引擎可见性、robots/noindex 区别、siteurl/home 例外。
- 补充 CPT/Taxonomy 配置、空归档与 Soft 404、HTTP 状态码和真实分页。
- 强化主题/插件冲突与多 JSON-LD 实体判别、Canonical 提示性质、结构化数据适用性。
- 补充首屏图片懒加载、CWV 现场数据与 Lighthouse 的区别。
- 强化 hreflang 互返、跨域及同语言地区版本的规范化判断。
- 提供每项检查范围和证据要求；统一四态定义。
- 强化缓存与发布后回归复测。

## 不直接采纳的绝对化意见

- 不要求 WordPress siteurl 与 home 在所有安装架构下完全相等。
- 不把所有空归档强制设为 404/410。
- 不把“必须一个 H1”作为 Google 搜索硬要求。
- 不要求所有页面无条件设置自引用 Canonical。
- 不认为多个 JSON-LD 脚本一定冲突。
- 不要求每次修改后无差别清空所有缓存。
- 不开发评分、爬虫、数据库或任务管理。

## 验收范围

对 38 项编号、JSON 格式、链接协议、脚本语法、静态页面元素和 ZIP 包完整性进行自动检查。真实移动浏览器和打印机的视觉验收仍需人工确认。
